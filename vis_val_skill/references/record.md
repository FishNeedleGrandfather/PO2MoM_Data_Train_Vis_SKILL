# 实验记录与周志

编辑前读项目根目录的 `record.md`、`Weekly Journal.md` 和对应原始日志/结果 JSON。不要凭最新曲线图反推出缺失的电流 error。

## `record.md`

- 沿用现有结构和连续序号；先查完整记录的已用编号，再选未占用的新编号。表格、文字、loss 曲线标题和图片说明保持同一序号，不挤乱顺序或重用编号。现有编号索引见 [history.md](history.md)，不是新任务的默认值。
- 每条至少给出数据/划分、脚本和 checkpoint、训练完成/最佳 epoch、指标定义和单位、训练/验证/测试归属、PO 基线、预测结果及计算来源。未复算的值写“未复算”；失败、训练 bug、超出 PO error 的负例也保留，并写明为什么不能用于能力判断。
- Loss 图从逐轮日志生成，标清 train/val、epoch、最佳点及异常截断；图片路径必须实际存在。`record_assets/loss_curves` 保存曲线图，`record_assets/weekly_journal` 保存单站 RCS 等图。数值优先由日志或评估结果重算，图形只辅助说明。
- 图中的电流、RCS RMSE、修正量 MSE 单位和样本汇总方式分开；不同归一化、不同数据集及 FEKO 原生/积分估算远场要写出限制。像关闭网络通路但不重训的消融，只能说明当前权重依赖，不当作重新训练后的架构比较。

## `Weekly Journal.md`

以新的 `# 周志 YYYY/MM/DD` 独立 section 追加，保持旧周志和日期导航。按任务写数据划分表、结果（引用已核实的 record loss/error 与曲线）、局限或下一步。图与相对路径需存在，负面泛化结果也如实描述。不要把上传包内旧 HTML 误认为 Markdown 已同步；网站更新须按发布参考文件处理。
